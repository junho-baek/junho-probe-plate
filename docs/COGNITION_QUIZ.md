# 인지 퀴즈 설계

## 목적

인지 퀴즈는 암기식 기술 면접이 아닙니다. AI가 만든 산출물에 대해 본인이 구조, 선택 이유, 동작,
실패 조건을 실제 저장소와 모순 없이 설명하는지 확인합니다.

## 출제 규칙

- 실제 프로젝트를 읽은 뒤에만 출제합니다.
- 각 문항은 하나 이상의 검증된 `file:line`을 갖습니다.
- 관련 의도 이벤트가 있으면 실제 event ID를 연결합니다.
- contemporaneous event가 있으면 코드와 이벤트를 함께 묻는 문항을 최소 2개 냅니다.
- agent orchestration이 실제 구현됐다면 Producer·Judge·deterministic gate 경계 문항을 반드시 포함합니다.
- SET에서는 모범답안과 정답 요약을 공개하지 않습니다.
- 문서를 닫고 한 문항씩 답합니다.

## 좋은 문항 형태

```text
I-014에서 preview parity를 완료 조건으로 바꾼 뒤 실제 renderer 구조가 어떻게 달라졌나요.
요청이 Admin에서 고객 화면까지 흐르는 파일 순서와, 어느 조건에서 둘이 다시 어긋날 수 있는지 설명하세요.
```

## 판정

답은 다음 조건을 모두 만족해야 합니다.

- 실제 제출물과 모순되지 않음
- 일반론이 아니라 본인 산출물 기준
- 없는 파일·API·수치를 만들지 않음
- 권위가 아니라 증거로 추론함

코드나 intent event와 충돌하는 유창한 답은 `unmet`입니다. 모르는 것을 모른다고 답한 경우도
`unmet`이지만 무결성 위반으로 보지는 않습니다.
