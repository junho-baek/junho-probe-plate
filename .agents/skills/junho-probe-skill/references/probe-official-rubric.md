# Probe 공식 평가 기준 (단일 기준 문서)

**출처**: <https://www.getcofa.com/ko/probe> · **확인일**: 2026-09-27
**지위**: 이 파일의 「공식」 절은 Cofa 제품 페이지 문구에 근거한다. 「비공식」 절은 추론이거나 이 스킬의 자체 관례다. 두 절을 섞지 말 것.

Probe는 KRAFTON의 정규 채용 평가 테스트로 제공되며 사내 전 직군으로 확대 중이다. 이 스킬은 Probe형 평가 전반에 쓰며, 특정 행사(Cofathon 등)에 한정되지 않는다.

---

## 공식 — 세 축과 평가 근거 채널

> "산출물을 직접 장악하는 '기술', 과정을 조향하는 '의도', 결과를 이해하는 '인지'의 **세 축**으로 평가해요."

축은 **세 개**다. 각 축은 **서로 다른 근거 채널**에서 채점된다. 이것이 전략을 결정한다.

| 축 | 정의 | 채점 근거 |
| --- | --- | --- |
| 기술 관리 (Technique) | AI가 만든 산출물을 본인이 직접 장악해, 실제로 돌아가게 · 유지 가능한 구조로 · 보안이 새지 않게 코드를 잘 구성하는가 | **산출물 · 코드** |
| 의도 관리 (Intent) | AI에게 일을 맡기고 조향하며, 목표와 제약을 정의하고 작업을 분해해 위임하고, 검증 루프로 결과를 통제하는가 | **행동** (자동 수집된 기록) |
| 인지 관리 (Cognition) | AI의 작업과 산출물을 이해하고, 왜 이 구조인지 · 어떻게 동작하는지 · 어디서 깨지는지 본인 산출물 기준으로 설명할 수 있는가 | **사후 Q&A** |

채널이 다르다는 사실의 함의:

- **인지는 문서로 보완할 수 없다.** 사후 Q&A에서 말로 설명해야 한다.
- **의도는 작업 후기로 보완할 수 없다.** 실제 프롬프트·도구 설정·검증 실행 흔적에서 읽힌다.
- **기술은 서술로 보완할 수 없다.** 코드와 실행 결과가 근거다.

## 공식 — 세부 rubric

"각 역량은 세부 rubric으로 채점해요. 기준마다 점수가 책정되며 충족 · 미충족 예시를 그 근거가 되는 프롬프트, 소스코드와 함께 제시해 평가자에게 신뢰 가능한 지표를 전달해요."

### 기술 관리 — 산출물 · 코드로 평가 (3개)

1. **기능 · 실행성** — 실제 환경에서 깨끗하게 돌아가는가
2. **격리 · 구조화** — 유지 · 확장 가능한 구조로 만들었는가
3. **보안 위생** — 시크릿 · 민감정보가 코드 · 로그로 새지 않는가

### 의도 관리 — 행동으로 평가 (6개)

1. **Output 목표 구체화** — AI에게 맡긴 일이 어떤 상태가 되면 끝나는지를 정의하는가
2. **문제 상황 · 제약 정의** — AI가 추측하지 않도록 맥락과 경계를 제공하는가
3. **의도 갱신 · 맥락 유지** — 새 정보와 실패가 생겼을 때 지시와 기록을 갱신하는가
4. **작업 분해 · 위임 설계** — 큰 문제를 점검 가능한 실행 단위로 쪼개 맡기는가
5. **재사용 가능한 작업 체계** — 반복 작업과 맥락 전달을 문서 · 도구로 고정하는가
6. **검증 루프 설계 · 통제** — AI 결과를 그대로 믿지 않고 검증 → 수정 → 재검증으로 닫는가

### 인지 관리 — 사후 Q&A로 평가 (3개)

1. **AI 의사결정 · 근거 이해** — AI가 택한 구조와 기술이 무엇이고 왜인지 설명하는가
2. **AI 산출물 구조 이해** — AI가 만든 것의 실제 구성과 연결을 설명하는가
3. **AI 산출물 동작 · 리스크 예측** — 정상 · 비정상 경로의 동작과 깨질 조건을 예측하는가

## 공식 — 모든 답변에 공통 적용되는 판정 기준

세 축 모두에 같은 문구로 붙어 있다. 사실상 가장 강한 감점 장치다.

- 실제 제출물과 **모순되지 않는가**
- 일반론이 아닌 **본인 산출물 기준**인가
- **없는 것을 지어내지 않는가**
- 권위가 아닌 **증거로 추론하는가**

## 공식 — 충족으로 보는 신호

- 완료 조건 · 수용 기준이 명시된 프롬프트
- 실패 → 수정 → **같은 검증으로 재통과**한 기록
- 결정 이유와 **기각한 대안**의 기록
- 새 세션이 이어받을 수 있는 **의도 문서 (CLAUDE.md)**
- 실제 제출물과 일치하는, 본인 산출물 기준의 답변

## 공식 — 미충족으로 보는 신호

- '알아서 잘 만들어줘'식의 **통짜 위임**
- AI의 완료 보고를 **검증 없이 수용**
- **교과서 일반론**으로 채운 답변
- **없는 파일 · API를 인용**하는 설명
- **도구 · MCP 남발**로 흐려진 신호

## 공식 — 평가 환경과 절차

1. **실전 환경에서 시작** — 브라우저 웹 IDE로 바로 시작. mock이 아닌 **실 API · 실 컴퓨트** 환경에서, **시간과 토큰 budget** 안에서 작업한다.
2. **산출물 · 과정 기록 자동 수집** — 소스 코드와 함께 transcript, 프롬프트, 도구 설정, 검증 실행 흔적 같은 AI 협업 기록이 자동 수집된다. **지원자는 따로 서술하지 않는다.**
3. **사후 Q&A** — 결과물 · 의도 · 인지에 고루 걸쳐 출제되며, 본인 결과물을 설명할 수 있어야 한다.
4. **자동화된 평가 · 면접 리포트** — 역량별 세부 rubric으로 자동 채점하고 후보별 변별 리포트를 만든다. 기준마다 **grey area**와 충족 · 미충족 예가 정의돼 **채점이 재현 가능**하다.

"모델 성능과 범위에 제한을 두지 않고 실제 업무 환경과 동일한 자유도로" 지원한다.

## 비공식 — 이 스킬의 관례와 추론

아래는 공식 문서에 없다. 공식 기준처럼 인용하지 말 것.

- **축 가중치와 총점은 공개되지 않았다.** 100점 만점이나 축별 배점을 만들어내지 않는다. 세부 기준별로 채점하고 축별로 `합계/만점`(기술 15 · 의도 30 · 인지 15, 0-5 척도 기준)만 보고한다. 단일 합계가 필요하면 "이 스킬의 자체 관례"라고 명시한다.
- **「소통 관리」는 공식 축이 아니다.** 2026-07 Cofathon 준비 문서는 4번째 축으로 소통 관리를 기재했으나 공식 Probe 문서는 세 축만 명시한다. 요구사항 발굴·이해관계자 모호성 해소는 공식 **의도 관리 2번(문제 상황 · 제약 정의)** 으로 채점하고, 남는 부분은 점수에 넣지 않는 **선택 렌즈**로만 쓴다.
- **자동 수집과 제출 산출물은 별개다.** Probe는 협업 기록을 자동 수집하므로 별도 서술이 불필요하지만, 개별 행사가 `README.md`·`AI_COLLABORATION.md` 같은 문서를 따로 요구할 수 있다. 행사 요구사항이 있으면 그것을 따른다.
- **grey area가 사전 정의돼 있다**는 것은 경계선 판정을 관대하게 기대할 수 없다는 뜻으로 읽는다. 애매한 위치가 아니라 명확히 충족 쪽에 놓는다.
